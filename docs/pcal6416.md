# PCAL6416A — U4 on the top board

A 16-bit I2C GPIO expander (NXP PCAL6416A, 24-pin HWQFN) on the stock 1914 **top board**. It reads most of the face/shoulder buttons and sends them to the bottom board over I2C through J3. Tasks related to it are tracked in [[todo#PCAL6416 expander (top board)]].

Sources:
- [[references/XB1 1914 TOP BOARD.pdf]] — schematic (read from a high-resolution render)
- [[references/PCAL6416A-datasheet.pdf]] — NXP datasheet Rev. 7.1 (30 Aug 2022). Section numbers below refer to this document.

## Key specs

| Parameter | Value | Datasheet |
|---|---|---|
| Supply (VDD(I2C-bus), VDD(P)) | 1.65–5.5 V; both at **3.3 V** here | §1 |
| I2C speed | **400 kHz max** (Fast-mode) | §2 |
| Address | `0b010000A`, so ADDR high → **`0x21`** | §7.1, Table 5 |
| Standby current (fSCL = 0, inputs static) | 1 µA typ / 3.2 µA max (VDD(P) 2.3–3.6 V) | Table 34 |
| Active current (400 kHz continuous reads) | 40 µA typ / 75 µA max | Table 34 |
| Internal pull-up/down | 100 kΩ typ (50–150 kΩ) | §7.4.8, Table 34 |
| Port inputs | 5 V tolerant, 0.7×/0.3× VDD(P) thresholds | §2, Table 32 |
| Reset pulse / recovery | tw(rst) ≥ 30 ns, trec(rst) ≥ 200 ns, trst 600 ns | Table 36 |
| Power-up state | All pins inputs, **pull-ups/downs disabled**, interrupts masked | §7.4, Table 6 |

## Connections

| U4 pin | Name | Connected to | Notes |
|---|---|---|---|
| 23 | VDD(I2C-bus) (VCCI) | 3.3 V | Sets the SDA/SCL logic level, compatible with nRF I/O at 3.3 V |
| 21 | VDD(P) (VCCP) | 3.3 V | Core + port supply |
| 18 | ADDR | 3.3 V | → address **0x21** |
| 20 | SDA | R41 → TP30 → **J3 pin 7** | C36 51 pF to GND on the J3 side |
| 19 | SCL | TP31 → **J3 pin 5** | C46 100 pF to GND on the J3 side |
| 22 | ~INT | **Not connected** | Button reads must be polled |
| 24 | ~RESET | R4 (0 Ω) → **J3 pin 9** | EG2 (ESD) + C37 to GND. The same net holds the power latch on, see below |
| 9, 25 | VSS, EPAD | GND | |

> [!important] Reset is tied to the power hold line
> J3 pin 9 also drives the power latch (R7 → D26 → Q9 gate). The expander is **in reset whenever the power hold is released**. It also power-cycles with the 3.3 V rail, so its configuration is lost every time the controller turns on. Configure it again after asserting the hold.

> [!question] I2C pull-ups
> The top board has no I2C pull-ups near U4, and the datasheet requires them (§5.2, Table 3). They're most likely on the stock SoC/bottom board. **Plan pull-ups on the new bottom board** (e.g. 4.7 kΩ to 3.3 V; lower is fine at 400 kHz with C46/C36 on the lines) and confirm there are none on the top board.

## Register map

Verified against the datasheet (§7.3, Table 6).

| Cmd | Register | Access | Power-up | Our setting |
|---|---|---|---|---|
| `0x00` | Input port 0 | R | pin state | **Read every cycle** |
| `0x01` | Input port 1 | R | pin state | **Read every cycle** |
| `0x02` / `0x03` | Output port 0 / 1 | R/W | `0xFF` | Unused |
| `0x04` / `0x05` | Polarity inversion 0 / 1 | R/W | `0x00` | Optional: `0xFF` so that pressed reads as 1 |
| `0x06` / `0x07` | Configuration 0 / 1 (1 = input) | R/W | `0xFF` | Leave (all inputs) |
| `0x40`–`0x43` | Output drive strength | R/W | `0xFF` | Unused |
| `0x44` / `0x45` | Input latch 0 / 1 | R/W | `0x00` | Leave off (see note) |
| `0x46` / `0x47` | Pull-up/down **enable** 0 / 1 | R/W | **`0x00`** | **`0xFF`** — must be written |
| `0x48` / `0x49` | Pull-up/down **select** 0 / 1 (1 = pull-up) | R/W | `0xFF` | Leave (already pull-up) |
| `0x4A` / `0x4B` | Interrupt mask 0 / 1 | R/W | `0xFF` | Leave (INT not connected) |
| `0x4C` / `0x4D` | Interrupt status 0 / 1 | R | `0x00` | Unused |
| `0x4F` | Output port configuration | R/W | `0x00` | Unused |

> [!note] Register pairs, not auto-increment (§8.1, §8.2)
> Registers work in **pairs**. After the first byte, further bytes read from or write to the *other* register of the pair, alternating back and forth. They don't advance to the next address.
> - One write of `[0x46, 0xFF, 0xFF]` sets both pull-enable registers.
> - One read starting at `0x00` returns `Input0, Input1, Input0, …`.
> - The pointer stays on that pair after a read (§8.2), so repeated polls can **skip the command byte** as long as each read is an even number of bytes.

> [!note] Input latch
> The input latch (`0x44`/`0x45`) keeps a changed input value until the input register is read (§7.4.6). With 1 ms polling, the only benefit is catching presses shorter than 1 ms, which is unnecessary for buttons. Leave it off.

## Firmware notes

### Startup sequence
1. Boot → drive J3 pin 9 high (power hold + releases expander reset). Wait ≥ 200 ns before the first I2C access (trec(rst)), which is effectively immediate.
2. Write `[0x46, 0xFF, 0xFF]` to enable the pull-ups on all 16 pins. The pull-up select defaults to pull-up already.
3. Optional: write `[0x04, 0xFF, 0xFF]` for polarity inversion, so that pressed reads as 1.
4. Do a first read at `0x00` to set the pointer, then poll once per report cycle.

> [!warning] Inputs float until step 2
> At power-up the pull-ups are **disabled** and there are no external pull-ups, so the button inputs float. A floating input can add up to 80 µA of supply current per pin (ΔIDD, Table 34) and reads as garbage. Do step 2 as early as possible, and ignore button reads until it's done.

### Polling cost
| Transaction | Bits on the bus | Time at 400 kHz |
|---|---|---|
| With command byte: `S addr+W 0x00 Sr addr+R d0 d1 P` | ~45 | ~115 µs |
| Pointer already set: `S addr+R d0 d1 P` | ~27 | ~70 µs |

Either fits comfortably in a 1 ms report cycle.

### Current
- Idle, buttons released: ~1 µA standby plus ~40 µA while polling continuously.
- Each **held** button draws 3.3 V / 100 kΩ ≈ **33 µA** (22–66 µA across the resistor tolerance) through its pull-up.
- When the controller is off, the whole 3.3 V rail is down, so it draws nothing. It only matters while running or USB-powered.

### Code

```c
#define PCAL6416_ADDR        0x21

#define PCAL_REG_INPUT0      0x00
#define PCAL_REG_POLARITY0   0x04
#define PCAL_REG_CONFIG0     0x06
#define PCAL_REG_PULL_EN0    0x46
#define PCAL_REG_PULL_SEL0   0x48

#define BTN_SHARE  (1u << 0)
#define BTN_X      (1u << 1)
#define BTN_Y      (1u << 3)
#define BTN_RB     (1u << 4)
#define BTN_LB     (1u << 5)
#define BTN_MENU   (1u << 7)
#define BTN_PAIR   (1u << 8)
#define BTN_DUP    (1u << 9)
#define BTN_DRIGHT (1u << 10)
#define BTN_DLEFT  (1u << 11)
#define BTN_DDOWN  (1u << 12)
#define BTN_VIEW   (1u << 13)
#define BTN_A      (1u << 15)
#define BTN_UNUSED_MASK ((1u << 2) | (1u << 6) | (1u << 14))

/* raw = Input0 | (Input1 << 8); active-low without polarity inversion */
static inline uint16_t pcal_buttons(uint16_t raw)
{
    return (uint16_t)(~raw) & (uint16_t)~BTN_UNUSED_MASK;
}
```
